    15→- Built `src/lib/ludo/engine.ts` — full Ludo rules:
    16→  - 52-cell main track, 6-cell home columns, 8 safe squares (4 starts + 4 stars).
    17→  - Token position encoding: -1 = base, 0..51 = track, 100..105 = home column, 200 = finished, -999 = invalid (overshoot).
    18→  - Classic rules: roll 6 to release, 3 sixes → pass turn, capture on non-safe squares, exact-roll-to-finish (no overshoot).
    19→  - **TWIST MODE (user request)**: tokens on the main track OR home column can also move BACKWARD by the dice value, bounded by the player's own start square (cannot go below it). Backward moves can also capture opponents on non-safe squares.
    20→  - Auto-pass when no legal moves; auto-reroll on 6 (unless seat just finished).
    21→- Built `src/lib/ludo/bot.ts` — heuristic bot AI (finishing > capturing > escaping danger > releasing > advancing). Includes `randomBotName()` and `botThinkDelay()` (~700-1500ms).
    22→- Built `src/lib/ludo/board.ts` — 15x15 board geometry: TRACK_CELLS[52], HOME_COLUMN_CELLS per color, BASE_DOCKS per color, BASE_REGIONS, STAR_CELLS, `posToCell()` converter, Tailwind color class maps.

    26→- Game engine is the single source of truth for rules; the websocket mini-service will import it as the authority; the React UI will import the geometry + read-only state for rendering.

Backward moves are clamped at the token's own start square. Captures still apply on backward landings. This is the `mode: 'twist'` setting on the GameState.

   242→Work Log:
   243→- Created `/home/z/my-project/mini-services/game-service/` as an independent bun project.
   244→- `package.json` — name `ludo-game-service`, scripts `dev` (`bun --hot index.ts`) and `start` (`bun index.ts`). Deps: `socket.io`. DevDeps: `@types/socket.io`, `bun-types`.
   245→- `index.ts` — socket.io server, port 3003 (hardcoded), path `/`, CORS `*`, pingTimeout 60s, pingInterval 25s. Imports the ludo engine + bot AI DIRECTLY via relative path (`../../src/lib/ludo/engine.ts` / `bot.ts`) — bun supports native TS, no copy needed. Documented in code header.
   246→- In-memory stores: `rooms: Map<roomId, RoomState>` and `sockets: Map<socketId, {userId, roomId}>`.
   247→- RoomState carries: id, code, mode, maxPlayers, botCount, seats (SeatState[]), gameState, hostUserId, createdAt, botTimer, destroyTimer.
   248→- SeatState: { seat, userId, isBot, name, socketId, ready, disconnected?, forfeited?, joinedAt }.
   249→- Room codes: 6-char uppercase alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no 0/O/1/I confusions). `room:join` with unknown code creates the room (host = joining user). `room:create` generates a fresh code and creates.
   250→- Game start: validates all humans ready (when >1 human), re-orders seats so humans come first (in seat order) then bots, fills remaining seats with bots up to maxPlayers, calls `createInitialState`, broadcasts `game:started` then `game:state`, kicks off bot loop if first seat is a bot.
   251→- Bot turn flow: `scheduleBotTurn(room)` — clears any existing bot timer, and if current seat is a bot, schedules a `setTimeout(botThinkDelay())` that:
   252→  - phase `roll` → `applyRoll`, broadcast, recurse.
   253→  - phase `move` → `chooseBotMove` → `applyMove`, broadcast, recurse.
   254→  - phase `gameover` → `endGame`, broadcast `game:over`, stop.
   255→  Only ONE bot timer per room at any time; cleared on game over / room destroy / state reset.
   256→- Disconnect handling: marks seat `disconnected=true`, `socketId=null`. Mid-game disconnect = forfeit (push seat to `winners`, pass turn if it was theirs, re-check game over, schedule bot turn if next seat is bot). Lobby disconnect = remove seat. If all humans have left mid-game → endGame immediately. Starts a 60s destroy timer that nukes the room if no human reconnects. Empty rooms are destroyed immediately.
   257→- Validation: `game:roll` / `game:move` from non-current-seat sockets → ignored + `room:error`. `game:move` with illegal `{tokenId, direction}` (not in `state.legalMoves`) → ignored + `room:error`. `room:add-bot` / `room:remove-bot` / `room:start` are host-only. `room:start` rejected if game already started or fewer than 2 seats filled.
   258→- Chat: `chat:message { content }` broadcast as `{ userId, username, content, timestamp }` to all sockets in the room. Content truncated to 500 chars.
